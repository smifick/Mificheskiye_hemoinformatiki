# Три гипотезы тяжёлого хвоста SI: scaffold benchmark v5

Выполнены все три гипотезы на 320 организаторских строках. Новые архитектурные гипотезы не улучшили невзвешенную MSE относительно raw KRR на тех же scaffold-фолдах. Дополнительный контроль LightGBM с signed-log дескрипторами дал MSE 18 755 172.81 (−0.75% к raw KRR), но не решил проблему экстремального SI и не даёт основания утверждать устойчивое улучшение.

## Код и протокол

- [Модели, признаки, замороженные эмбеддинги и sample weights](../src/si_tail.py).
- [Воспроизводимый CLI benchmark](../src/benchmark_si_tail.py).
- [Тесты](../tests/test_si_tail.py), [дополнительные зависимости](../requirements-si-tail.txt).
- [Основные результаты](../results/si_tail_v5/), [signed-log проверка](../results/si_tail_v5_signedlog/).

Данные: `data/raw/train.csv`, загружаются **только SMILES и SI VACV**. Test, IC50, CC50, пропуски концентраций, культура, штамм и названия не читаются. Внешние SI не добавляются. Целевая колонка не фильтруется и не переопределяется: README исходного проекта описывает 81 техническую метку 10000 и два технических нуля. Следовательно, общая MSE оценивает предоставленную соревновательную цель, а не исключительно измеренный биологический SI.

Стандартизация: родительская молекула, нейтрализация, канонический таутомер. Morgan radius=2, 2048 бит, хиральность; 217 RDKit-дескрипторов. Группы — исторические обобщённые Bemis–Murcko с объединением групп, если канонический таутомер совпадает; все ациклические структуры в одной группе. В данном наборе 117 групп и 312 канонических таутомерных структур.

Внешняя проверка: GroupKFold, 5 фолдов, shuffle=True, seed=2718; размеры валидации 59, 59, 54, 102, 46. Внутри каждой обучающей части: 3 scaffold-фолда, seed=2718+outer_fold+1. Преобразования с обучаемыми параметрами (imputer, StandardScaler), веса смеси, сила регуляризации и политика sample weighting используют только внутренние обучающие данные. `fit_outer_fold` не принимает валидационные метки. Итоговая MSE вычисляется как среднее квадратов всех 320 OOF-ошибок, без весов и без усреднения неравных фолдов с равными коэффициентами.

Фиксированные диагностические пороги: малые SI ≤ 100 (200 строк), хвост SI ≥ 10000 (82 строки, включая технические коды). Экстремальный SI > 10000 — единственная строка, row_index=14, source_row=16. Для неё отдельно сохраняются абсолютный разрыв, квадрат ошибки и доля общей SSE. Ни Huber, ни обрезание прогнозов сверху или снизу не используются. Отрицательные регрессионные прогнозы также остаются в MSE и учитываются диагностически.

RDKit-признаки и frozen-эмбеддинги можно один раз извлечь и кешировать для всех SMILES: этот шаг не обучает статистику по выборке и не имеет доступа к y. Масштабирование, заполнение пропусков и любой выбор по MSE выполняются заново внутри фолдов.

## Гипотеза 1: Raw + Log1p

`RawLogEnsemble` — sklearn-совместимый класс, клонирующий два регрессора. В benchmark оба — Tanimoto KernelRidge(alpha=1). Для каждой обучающей части получены внутренние групповые OOF-прогнозы raw и expm1(log1p). scipy.optimize.minimize (L-BFGS-B, аналитический градиент) минимизирует невзвешенную raw MSE, после чего модели переобучаются на всей обучающей части внешнего фолда.

Смесь ограничена w_raw ≥ 0, w_log ≥ 0, w_raw+w_log=1. Это прозрачная смесь двух прогнозов без свободной экстраполяционной поправки. Деление целевой функции оптимизатора на постоянный обучающий второй момент y улучшает численную устойчивость и не меняет минимум MSE. На всех пяти внешних обучающих частях получены **w_raw=1, w_log=0**. Ансамбль воспроизводит raw KRR: преимущество не получено. Внутренняя MSE обученной смеси — диагностическая оценка калибровки, а внешние OOF-метрики оценивают всю процедуру.

## Гипотеза 2: Frozen ChemBERTa + RDKit

transformers.AutoTokenizer/AutoModel, модель `DeepChem/ChemBERTa-77M-MTR`, неизменяемая ревизия `66b895cab8adebea0cb59a8effa66b2020f204ca`. Модель в eval(), все параметры requires_grad=False, вычисление в torch.inference_mode(). Используется masked mean последнего hidden state, без BOS/EOS и padding; pooler не нужен. Размер эмбеддинга 384; после объединения с RDKit — 601 признак. Максимум входных токенов 143 при допустимых 512, усечения нет. Длинные SMILES вызывают явную ошибку. Ключ кеша зависит от упорядоченных канонических SMILES, ревизии модели и pooling; метки не входят в кеш.

Проверены отдельные эмбеддинги с Ridge, объединённые признаки с Ridge и с LightGBM. Alpha Ridge выбирается из 100, 1000, 10000 по внутренней невзвешенной scaffold-OOF MSE. Pipeline: медианный imputer → StandardScaler → Ridge. Контроль — Ridge только на RDKit. LightGBM: regression_l2, 350 деревьев, learning_rate=0.03, max_depth=8, num_leaves=31, min_child_samples=12, reg_lambda=100, reg_alpha=1, max_bin=63. Параметры заморожены; early stopping по внешним меткам отсутствует.

Первый прогон обнаружил численную неустойчивость Ridge на исходных RDKit-дескрипторах: у source_row=234 дескриптор Ipc=2.876e16, после обучающего StandardScaler его величина около 186197. Прогноз объединённой Ridge около −1.95 млн приводит к MSE 1.184e10. Этот отрицательный результат сохранён целиком. **После его изучения** выполнена дополнительная проверка signedlog(x)=sign(x)*log1p(abs(x)) только для RDKit-признаков, до обучаемого масштабирования. Это не преобразование y и не clipping прогнозов. Она устраняет численную катастрофу, но ChemBERTa всё равно не улучшает MSE относительно контроля.

## Гипотеза 3: Sample weighting

Одни и те же Morgan+RDKit признаки и параметры LightGBM у взвешенного и невзвешенного контроля. Внутри каждого fit используются только его y:

```
signal = y                       # raw
signal = log1p(y)                 # log
u = 1 + strength * signal / mean(signal)
weights = u / mean(u)
```

Все веса положительны, среднее равно 1; для нулевой обучающей цели веса единичные. Сила усиления — 0.5, 1, 2. Во вложенной процедуре среди 7 вариантов присутствует uniform, чтобы разрешить отказ от усиления. Схема выбирается по обычной внутренней OOF MSE; внешняя MSE всегда невзвешенная. Кроме вложенной процедуры независимо показаны фиксированные log(strength=1) и raw(strength=0.5).

В основном прогоне вложенный выбор: uniform, log(0.5), log(0.5), uniform, log(0.5). Относительно невзвешенного LightGBM общая MSE увеличилась на 4.50%, при фиксированном log — на 6.01%, при raw — на 15.88%. MSE малых SI выросла соответственно на 17.06%, 46.71% и 73.53%. Значит, усиление хвоста в среднем наносит заметный ущерб малым значениям. Улучшение агрегированного tail_MSE при фиксированном log в основном относится к области, содержащей технические метки 10000; прогноз единственной молекулы с SI=36066.667 ухудшился.

## Что произошло с экстремальным SI

У единственной экстремальной молекулы y=36066.667, внешний fold=3, в его обучении max(y)=10000. Контроль KRR даёт 1585.24, разрыв 34481.42. В основном прогоне ChemBERTa+RDKit LightGBM даёт 1929.36 (разрыв меньше лишь на 1.00%), фиксированное raw weighting — 2101.72 (меньше на 1.50%), при этом общие MSE ухудшаются. Ансамбль не меняет прогноз.

После signed-log обычный LightGBM даёт 2218.13, разрыв 33848.53: уменьшение разрыва относительно KRR всего 1.84%. RDKit-only Ridge даёт 2853.48, но проигрывает KRR по общей MSE на 2.97% и по малым SI на 25.02%. Даже константа по обучающему среднему даёт 2702.81 для этой строки при худшей общей MSE. Рост единичного экстремального прогноза сам по себе не доказывает, что модель научилась хвосту.

На этой схеме текущий базовый прогноз — 1585.24, а не упомянутые около 271. Значение 271 из другого запуска нельзя использовать для прямого сравнения без воспроизведения той же модели и тех же фолдов. У исторической KRR в README MSE немного ниже (18 888 578.92), поскольку прежняя функция metrics обрезала отрицательные прогнозы до нуля; здесь такого преобразования нет.

Итог: **системного решения недопредсказания экстремума не получено**. В обучении проблемного фолда отсутствуют примеры нужного масштаба. Особенно ограничены обычные деревья, опирающиеся на средние в листьях; аддитивный бустинг может выходить за диапазон меток, но весами нельзя создать отсутствующую структурную информацию о хвосте. Одна экстремальная строка не позволяет надёжно оценить перенос в эту область. Следующий обоснованный шаг — независимые сопоставимые измерения с высокими SI и аудит технических меток, а не объявление выигрыша на одном примере.

## Проверки

39 тестов, включая 9 новых, прошли; также 8 subtests прежних тестов. Проверены независимость прогнозов и выбранных параметров от подмены внешних меток, локальный fit преобразований, непересечение scaffold-групп/канонических структур, оптимум веса ансамбля, невзвешенная MSE и отсутствие clipping, веса объектов, pooling без padding.

Дополнительно MSE всех 24 комбинаций модель/прогон независимо пересчитана из сохранённых OOF-прогнозов с rtol=1e-12; пересечений внешних и внутренних scaffold-групп нет. Реальная модель проверена на пяти SMILES при изменении порядка и batch_size: максимальное абсолютное расхождение эмбеддингов 3.875e-7; повторное чтение кеша совпадает точно. Версии, хеш train, ревизия ChemBERTa и диагностические размеры сохранены в protocol.json; проверки — в validation_report.json.

## Воспроизведение

Запуск из корня репозитория, Python 3.12:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install torch==2.15.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt -r requirements-si-tail.txt
HF_HOME=work/hf_cache HF_HUB_DISABLE_XET=1 TOKENIZERS_PARALLELISM=false \
  python src/benchmark_si_tail.py --out results/si_tail_raw_reproduced \
  --cache work/chemberta_cache --revision 66b895cab8adebea0cb59a8effa66b2020f204ca
HF_HOME=work/hf_cache HF_HUB_DISABLE_XET=1 TOKENIZERS_PARALLELISM=false \
  python src/benchmark_si_tail.py --out results/si_tail_signedlog_reproduced \
  --cache work/chemberta_cache --revision 66b895cab8adebea0cb59a8effa66b2020f204ca \
  --descriptor-transform signedlog
python -m pytest tests -q
```

Каталог --out должен быть новым, результаты не перезаписываются. Первая загрузка ChemBERTa требует доступа к Hugging Face; следующие запуски могут использовать кеш и зафиксированную ревизию. --skip-chemberta явно включает неполный classical-only benchmark, пропущенные модели не получают выдуманных метрик.

Для повторного использования класса:

```python
from si_tail import RawLogEnsemble, TanimotoRegressor
model = RawLogEnsemble(TanimotoRegressor(alpha=1), inner_splits=3, seed=2718)
model.fit(X_train, y_train, groups=scaffold_groups_train)
prediction = model.predict(X_valid)
print(model.weights_)  # raw, log
```

При импорте из другого скрипта добавьте src в PYTHONPATH. Каждый каталог результатов содержит comparison.csv, fold_metrics.csv, oof_predictions.csv, extreme_predictions.csv, validation_splits.csv, inner_splits.csv, training_selections.json, protocol.json. Итоговые submission.csv не заменялись: benchmark не читает test и не формирует соревновательную отправку.
